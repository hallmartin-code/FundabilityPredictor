# Financing Probability Report — Document Structure Template

The authoritative specification of the document the application produces. It
defines the sections, fields, formats, value domains and fixed text of the
one-page report, with no company data.

Companion artifacts in this folder, all regenerated by the same command:

| File | What it is |
| --- | --- |
| `report_template.pdf` | The one-page layout with placeholder tokens |
| `report_template.png` | Preview image of the same |
| `report_template.html` | The HTML companion layout |
| `lead_record_template.json` | Lead-record structure, all values null |
| `evidence_map_template.json` | Evidence map listing all 81 registry fields |

```bash
python docs/generate_template.py
```

The PDF template is rendered by the **production renderer** with placeholder
tokens rather than by a separate mock, so it cannot drift from real output.
Re-run the command whenever the layout or the field registry changes.

---

## Notation

| Notation | Meaning |
| --- | --- |
| `[FIELD NAME]` | A slot the application fills from the analysis |
| `XX%`, `XX`, `$X.XM`, `+X.X%`, `N` | Numeric slots; the token shows the format |
| Everything else | **Fixed structure** — headings, labels, units, disclaimers — reproduced verbatim in every report |

Two rules govern every slot:

1. **Never invent a value.** A field the source did not supply renders as
   `Not Provided`. It is never zero, never blank, never estimated into
   existence.
2. **Fixed text is fixed.** Section headings, flag labels, `/100`, the
   `3 MONTHS / 6 MONTHS / 12 MONTHS` captions, the market-condition
   disclosure, the confidentiality line and the disclaimer are part of the
   document's identity and must appear exactly as specified.

## Page specification

| Property | Value |
| --- | --- |
| Page size | US Letter (default) or A4, configurable |
| Page count | **Exactly one.** Enforced, never allowed to overflow |
| Margins | 34pt sides, 30pt top, 34pt bottom |
| Header band | 52pt, solid navy `#14213D` |
| Footer zone | 30pt, above the bottom margin |
| Body | Two equal columns with a 15pt gutter |
| Typeface | Helvetica / Helvetica-Bold / Helvetica-Oblique |
| Body size | 6.4pt–7.8pt, set by the density ladder |

**Fitting rule.** The renderer builds at the roomiest density, measures the
result, and steps down `comfortable → standard → tight → compact → dense`
until the content fits. The transparency block (§7) is the first thing dropped
when space is short. A final `KeepInFrame` scales the block if an unusually
long input defeats every rung. Long strings truncate on word boundaries with
an ellipsis; the company name auto-sizes to its band.

## Section 1 — Header band

```
[COMPANY NAME]                                    FINANCING PROBABILITY REPORT
[SECTOR]  |  [STAGE] (declared [DECLARED STAGE])  |  [GEOGRAPHY]
Target Raise $X.XM  ·  Committed $X.XM (XX%)  ·  Valuation $X.XM
```

| Slot | Source | Format | If absent |
| --- | --- | --- | --- |
| `[COMPANY NAME]` | `company_name` | Auto-sized 17pt→9pt, truncated to the band | `Not Provided` |
| `FINANCING PROBABILITY REPORT` | — | Fixed, right-aligned | Always shown |
| `[SECTOR]` | Classified sector label | Title case | `Not Provided` |
| `[STAGE]` | Model-inferred stage | One of the six stages | `Not Provided` |
| `(declared [DECLARED STAGE])` | `stage_declared` | Shown **only** when declared differs from inferred | Omitted |
| `[GEOGRAPHY]` | `headquarters` → `primary_geography` → `geographic_market` → `country` | First available | `Not Provided` |
| Target Raise | `target_raise` | `$X.XM` / `$XXXK` | `Not Provided` |
| Committed | `amount_committed`, `percent_committed` | `$X.XM (XX%)` | `Not Provided` |
| Valuation | `pre_money_valuation` → `note_cap` → `safe_cap` | `$X.XM` | `Not Provided` |

Showing both declared and inferred stage is deliberate: disagreement between
what a company calls its round and what its numbers imply is itself a finding.

## Section 2 — Probability of completing round

```
PROBABILITY OF COMPLETING ROUND

 ┌──────────┐ ┌──────────┐ ┌──────────┐   ┌─────────────────────────┐
 │   XX%    │ │   XX%    │ │   XX%    │   │ FUNDABILITY             │
 │ 3 MONTHS │ │ 6 MONTHS │ │12 MONTHS │   │ XX /100                 │
 └──────────┘ └──────────┘ └──────────┘   │ [READINESS LABEL]       │
                                          │ CONFIDENCE  [LEVEL] (XX)│
                                          └─────────────────────────┘
```

The three tiles occupy 63.5% of the content width; the score badge takes the
remainder.

| Slot | Domain | Format |
| --- | --- | --- |
| 3 / 6 / 12-month probability | 1–98 | `XX%`, 21pt bold, white on a colour-coded tile |
| Fundability score | 0–100 | `XX` at 15pt, `/100` at 8pt |
| `[READINESS LABEL]` | See below | 6.4pt bold, accent blue |
| `[LEVEL]` | `HIGH` / `MEDIUM` / `LOW` | Colour-coded |
| Confidence score | 0–100 | `(XX)` |

**Tile colour by probability:** ≥60 green `#1B7F4B` · 30–59 amber `#B7791F` ·
<30 red `#B03A2E`.

**Fundability labels** (fixed strings, band-mapped):

| Score | Label |
| --- | --- |
| 85–100 | `HIGHLY FINANCEABLE` |
| 70–84 | `FINANCING READY` |
| 55–69 | `NEARLY READY` |
| 40–54 | `MATERIAL GAPS` |
| 0–39 | `EARLY / HIGH RISK` |

These describe *fundraising readiness*, not investment quality.

**Invariants that must hold in every generated document:**

- `3-month ≤ 6-month ≤ 12-month`
- every probability within `1%–98%` — never 0% or 100%
- readiness score and confidence score are **independent**; a high readiness
  score must not force a high confidence level

## Section 3 — Probability drivers *(left column)*

```
PROBABILITY DRIVERS
▪ [Probability driver 1 of up to 5]
▪ [Probability driver 2 of up to 5]
…
```

Up to five positive signals actually detected in the source, most significant
first. Each is a short label, not a sentence.

If none were evidenced, print exactly:
`No positive financing signals were evidenced in the deck.`

## Section 4 — Critical blockers *(left column)*

```
CRITICAL BLOCKERS
CRITICAL [Blocker 1 title]
[Blocker 1 detail: one or two sentences naming the issue and quoting the
company's own figures]
```

Three to five blockers, ranked by severity.

| Element | Domain / format |
| --- | --- |
| Severity | `CRITICAL` (dark red) · `HIGH` (red) · `MODERATE` (amber) |
| Title | Short noun phrase, bold |
| Detail | One or two sentences, quoting the company's own figures |

Ordering is strictly `CRITICAL → HIGH → MODERATE`. If none, print exactly:
`No structural blockers identified.`

---

## Section 5 — Comparable financing profile *(left column)*

```
COMPARABLE FINANCING PROFILE
[COMPARABLE FINANCING PROFILE]
[One or two sentences explaining why the company fits this profile]

MARKET CONDITION ASSUMPTION: [ENVIRONMENT]
```

A qualitative archetype with a stated rationale. **It must never claim a
specific comparable transaction** — no named company, no named amount — unless
supporting transaction data actually exists.

The market-condition line is a required disclosure. With no live data feed it
reads `MARKET CONDITION ASSUMPTION: [ENVIRONMENT]`; only a verified live source
may change it to `MARKET CONDITION: [ENVIRONMENT] (verified)`.

Environments: `Highly Favorable` · `Favorable` · `Neutral` · `Difficult` ·
`Highly Difficult`.

## Section 6 — Five actions *(right column)*

```
FIVE ACTIONS TO INCREASE FUNDING PROBABILITY
1. [Action: a specific instruction naming the company's own numbers,
   milestones or counterparties] [IMPACT · TIMEFRAME]
   [Why this action matters to closing this round]
```

**Exactly five**, numbered, ordered by impact then timeframe.

| Element | Domain |
| --- | --- |
| Impact | `HIGH` · `MEDIUM` · `LOW` |
| Timeframe | `Immediate` · `30 Days` · `60 Days` · `90 Days` |
| Why | One sentence, grey, dropped at tight densities |

Each action must name the company's own numbers, milestones or counterparties.
Generic advice — "improve traction", "get more customers" — is a defect. When
the source has few gaps, actions come from a strengthening set that still
references the round size, stage and sector.

## Section 7 — TEN Capital assessment *(right column)*

```
TEN CAPITAL ASSESSMENT
Fit Score XX/100  ·  [RECOMMENDED NEXT STEP]
[One sentence explaining the recommended next step]

Raise >= $2M                YES    >= 25% committed            NO
>= 50% committed        UNKNOWN    Revenue >= $700K        REVIEW
Revenue generating          YES    Institutional round         NO
Lead investor identified UNKNOWN   Runway >= 9 months      REVIEW
Investor materials complete YES    Likely fundraising candidate NO
```

Fit score 0–100. Recommended next step is one of five fixed strings:

- `HIGH PRIORITY - Immediate fundraising discussion`
- `QUALIFIED - Schedule fundability review`
- `NURTURE - Improve milestones before active outreach`
- `EARLY - Reassess after additional traction`
- `NOT CURRENTLY QUALIFIED`

**The ten flags**, in this fixed order and wording, in a two-column grid:

| # | Label | Threshold |
| --- | --- | --- |
| 1 | `Raise >= $2M` | Target raise ≥ $2,000,000 |
| 2 | `>= 25% committed` | Round progress ≥ 25% |
| 3 | `>= 50% committed` | Round progress ≥ 50% |
| 4 | `Revenue >= $700K` | Annual revenue ≥ $700,000 |
| 5 | `Revenue generating` | Any revenue > 0 |
| 6 | `Institutional round` | Instrument, investors or stage imply a priced round |
| 7 | `Lead investor identified` | A lead is committed |
| 8 | `Runway >= 9 months` | Runway ≥ 9 months |
| 9 | `Investor materials complete` | Materials sufficient to run a process |
| 10 | `Likely fundraising candidate` | Overall verdict |

**Flag values are tri-state plus review:**

| Value | Colour | Meaning |
| --- | --- | --- |
| `YES` | Green | Confirmed |
| `NO` | Red | Confirmed negative |
| `UNKNOWN` | Grey | **The source was silent** |
| `REVIEW` | Amber | Needs human judgement |

`UNKNOWN` must never collapse into `NO`. Silence is not a confirmed negative,
and treating it as one would disqualify companies for a documentation gap. The
two revenue flags derive from the same evidence and can never contradict each
other.

## Section 8 — Model transparency *(full width, shown when space allows)*

```
HOW THE 6-MONTH PROBABILITY WAS REACHED    WHAT LIMITS CONFIDENCE
Baseline from readiness score XX/100: XX%  ▪ [Confidence note 1: what a
+X.X% [Positive signal detected]             specific missing input cost]
−X.X% [Negative signal detected]           ▪ [Confidence note 2 …]
−X.X% [SECTOR] sector financing dynamics
+X.X% Capital market environment: [ENV]    N of the model's critical fields
Final 6-month probability: XX%             were not provided; values shown as
                                           Not Provided were never inferred.
```

The probability bridge, up to nine steps: the baseline, then each adjustment
with its signed contribution (green positive, red negative), then the final
figure in bold. **The arithmetic shown must be the arithmetic performed** — the
displayed deltas are the applied values, and they must sum from baseline to
final.

The right side lists up to five confidence notes, each explaining what a
specific missing input cost, followed by the count of missing critical fields.

This section is dropped first when the page is tight.

                        Compiled on [DATE] by TEN Capital Network   [LOGO]

| Element | Rule |
| --- | --- |
| Model-based disclaimer | Verbatim, required |
| Full disclaimer | Verbatim, required |

Per TEN Capital document standards, the footer carries the compilation date,
attribution and logo on a single line.

## Value types

Every extracted value carries exactly one:

| Status | Meaning |
| --- | --- |
| `EXPLICIT` | Stated in the source document |
| `CALCULATED` | Derived arithmetically from explicit values |
| `ESTIMATED` | Inferred by the model from weaker evidence |
| `MISSING` | Not present and not derivable |

A `CALCULATED` value never overwrites an `EXPLICIT` one, and a derived value's
confidence never exceeds that of its weakest input. Human corrections are
recorded separately, preserving the extracted original in `extracted_value` —
overrides and extraction are never conflated.

---

## Scoring structure

Nine weighted categories totalling 100 points, in this fixed order:

| Category | Weight |
| --- | ---: |
| Traction & Revenue | 20 |
| Round Progress | 15 |
| Market Opportunity | 10 |
| Team | 10 |
| Financial Quality | 10 |
| Financing Terms | 10 |
| Product & Defensibility | 10 |
| Investor Fit | 10 |
| Fundraising Readiness | 5 |

The full per-category, per-signal breakdown appears in the lead record, not on
the one-page report.

**Traction is judged by sector norms.** Each sector carries a traction mode —
`revenue`, `milestone` or `hybrid` — that determines what counts as proof. A
pre-revenue company in a milestone sector must not be scored as though revenue
were expected.

## Companion outputs

Every analysis writes three files, named from the company:

```
[CompanyName]_Financing_Probability_Report.pdf
[CompanyName]_Financing_Probability_Data.json
[CompanyName]_Extraction_Evidence.json
[CompanyName]_Financing_Probability_Report.html   (optional)
```

`lead_record_template.json` and `evidence_map_template.json` in this folder
give the exact structure of the two JSON files.

**Consent block.** The lead record ends with a consent block whose fields
default to `null` — not `false`, and never `true`:

```json
"consent": {
  "analysis_consent": null,
  "ten_capital_contact_consent": null,
  "timestamp": null
}
```

`null` means nobody was asked. Only an explicit decision may set these, and
absence of consent must never be recorded as consent.
